# 書籍ライブラリの初回読み込み最適化
2026-10-24

原因：初回の暗号化coreが130,819,395 bytes。本文と図版が一括復号されていた。
変更：登録表・表紙・共通画面をcoreに残し、書籍データを既存のLOAD_BOOK_ASSETS経路から遅延復号。分割済み暗号文は並列取得し、ハッシュ名の暗号文はHTTPキャッシュを再利用する。認証・暗号方式・PBKDF2回数・ログアウト時の平文キャッシュ破棄は維持。
初回coreは5,377,785 bytes（約95.9%削減）。初回ファイル105、従来core1015ファイルの内容は分割後と全件一致。遅延対象38冊。既存の画像遅延12冊も維持。
ローカルOCRのpublish-book.mjsにも再分割処理を反映し、次回の書籍転送によるcore肥大化を防ぐ。build-private-bundle.mjsも全書籍を遅延対象とする。
単体試験：分割前後の全ファイル一致、暗号化往復、改ざん拒否、登録時の他書籍保持。実端末のログインから表示までの時間は別途測定が必要。
