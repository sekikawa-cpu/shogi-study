# DS検定の端末間同期の修正（2026-10-27）

利用者から、自宅PCと会社PCで計画のチェック・学習時間・問題の正答数・教材の既読が一致せず、会社PCには同期状態の表示もないという報告を受けた。会社PCのURL・実機が未確認のため、ローカルHTML版や古い画面を開いている可能性は未確定。

Firebaseの読み取り調査では、登録済みアカウントは所有者の1件であることを確認した。所有者UIDによる画面とFirestoreのアクセス制限は維持する。アクセス制限と、各端末の保存内容をクラウドへ送受信する処理は別の仕組み。

## 修正した処理

- 初回の同期では、端末の既存進捗を別のIndexedDBへ退避してから、クラウドに未保存の学習記録や進捗を回収する。初期状態の未学習データを進捗として送らない。
- 過去の正答数を両端末が持っている場合、回収時は合算せず最大値を採用して重複を防ぐ。通常の新しい回答は従来どおり操作単位の差分で加算する。過去の独立した回答イベントが残っていない場合、完全な内訳の復元は行わない。
- 未送信キューにある操作、クラウド側の削除、意図的に外された計画チェックを、古いローカル状態で上書きしない。
- 旧版の未送信操作にアプリ識別子がない場合も、操作IDを維持してDSの形式で送れるようにする。送信済みの操作は受領記録で再適用を防ぐ。
- 受信エラーを単なるログ出力で終わらせず、画面に表示する。送信キューが空でも、受信に失敗していれば「同期済み」と表示しない。
- エラー時の再接続と「再同期」ボタンを追加。通常の受信はDS専用のライブ監視を使い、他アプリの全履歴を定期的に読み直さない。利用上限エラーでは再試行間隔を延ばす。
- 自動回収前のスナップショットを「端末バックアップ」からJSONで保存できるようにする。
- 異なる学習アプリと思われるローカル行は画面上で除外し、保存領域からは削除しない。
- ローカルHTML版には「このPC・ブラウザ内だけの保存で同期しない」という案内と正規Web版へのリンクを追加。Web版の教材にこの案内を混入させない。

## 利用方法

両PCで https://shogi-study.com/ds-study/ または https://shogi-study.com/admin/ds-study/ を開き、所有者アカウントでログインする。ページを再読み込みし、上部に「再同期」「端末バックアップ」が表示されることを確認する。「同期済み」と時刻が出てから端末を切り替える。

同期表示がない古いローカルHTML版の履歴は、自動的にはWebサイトへ渡らない。そのブラウザの「設定 → JSONで書き出す」で保存し、Web版で「読み込む（統合）」を使う。今回、会社PCにしかないデータを直接読み取ったり、取り込んだりはしていない。

## 検証

`node --test ds-cloud/cloud-source.test.mjs ds-cloud/sync-model.test.mjs` で、別々の端末保存領域と共有バックエンドを使うテストを実施。

- 計画チェック・学習時間・正答数・既読の双方向反映。
- ローカルにだけ残った進捗の回収と、両端末が持つ同じ過去の正答数の重複防止。
- 受信だけ失敗した場合の表示と再接続。
- 旧版キューの送信と重複防止。
- クラウドで意図的に未読に戻した場合でも、適用前の端末データを退避して保持。

テストは実際の同期処理とIndexedDBを模した独立保存領域で行い、Firestoreの通信部分はテスト用バックエンドに置き換えている。会社PC上の実通信・社内ネットワーク制限は未検証。実際の学習データをテスト用の値で書き換えてはいない。
